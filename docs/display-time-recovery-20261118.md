# 结果站时间与汇总修复（离线候选）

基线是 `tcl-live-results` 的 `c27b24996afb2d9b4bb8137fca30eb47cfee16ce`。当前候选只在本地隔离测试目录。部署、触发计划及监控流程未变更。

- 京东按北京时间自然日出数，抖音和天猫淘宝按 06:00 切换广播日。各平台超三小时、未核验、当前不可用或不属于当前日期的记录退出当日汇总；旧京东分钟记录保留原日期。浏览器会随时间更新汇总及逾期提示。
- 页面分开显示本版采用的采集尝试、最近有效观测、最近完成任务和本版页面生成时间。实际发布时间可打开发布记录核对。缺时间保留未知，刷新计划过时后明确提示本页仍是旧版。
- 页面打开后，跨统计日或超过时限会同步更新汇总、店铺状态、指示灯和关注筛选。采样历史仍可展开。复制记录使用各店铺观测时间，未知时保留未知。
- 发布脚本继续只读取可用历史，下游另读取三个平台最近完成任务的状态。选中的京东成功日志再旧也不会掩盖新失败。读取失败或资料缺失时，不能推导平台健康。
- 时间线任务列表读取失败时，刷新脚本返回失败，由现有发布流程保留上次成功的页面。全链路 Shell 回归使用合成采集日志和本地 GitHub CLI 替身。
- 天猫时间线将访问和未执行占位分开。新版读取 `R329_TMALL_NOT_RUN`。旧版只在明确 `API_ACCESS_LIMIT`、实际访问顺序等于完整配置的已访问前缀、停机与访问同一广播日时，核对剩余的停机占位。若日志和台账仍不一致，时间线维持不显示。不会补造访问点或有效观测。

同一合成故障回放包括京东 7 间仅有两天前的分钟记录、抖音 7 个账号本日身份均未核验、天猫首店触发验证且其余 8 家未执行。旧版在当日汇总中误计历史京东，新版 23 个条目均为无法判断，并保留历史记录的实际日期。旧停机占位和新 NOT_RUN 标签均有专门用例，无明确停机证据时仍拒绝对账。

Node 22 本地回归覆盖 builder、时间线、渲染、浏览器脚本、复制格式的数据时间、午夜与 06:00 切日及脱敏。GitHub Pages 的真实发布行为和下一次真实采集未在离线测试中验收。
